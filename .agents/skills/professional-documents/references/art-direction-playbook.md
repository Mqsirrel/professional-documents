# Art Direction Playbook

Use this reference when the user asks for a document to look **professional, beautiful, polished, redesigned, premium, modern, academic, or like a designer made it**.

The goal is not to add more decoration. The goal is to make the visual system express the document's purpose.

## Decision tree

### Formal / academic
Use restrained typography, strong alignment, generous but efficient whitespace, conservative color, clear section hierarchy, and highly legible tables.

### Technical / engineering
Use a precise grid, compact metadata, diagrams, numbered procedures, code/identifier styling, and data-first visualizations.

### Business / executive
Optimize for scanning: executive summary, key takeaways, metrics, short sections, decision-oriented tables/charts, and strong page rhythm.

### Editorial / portfolio
Allow stronger art direction: expressive cover, asymmetric composition, larger display typography, photography/illustration, and intentional page-to-page variation.

### Study / roadmap
Make progression visible: timelines, milestones, dependency cues, comparison tables, and repeatable study-module patterns.

## One visual concept per document

Select one primary design concept and express it consistently through:

- typography
- grid
- accent color
- table grammar
- section markers
- header/footer
- cover
- figure treatment

Do not combine unrelated concepts such as corporate cards + Japanese minimalism + neon gradients.

## Cover formula

A strong cover normally contains only what is needed to establish identity:

**title → context/subtitle → owner/institution → date/version**

Use composition, typography, whitespace, and a restrained visual motif. Decorative imagery must reinforce the topic. Never bake critical text into a background image when editable Word text is possible.

## Inside-page formula

A polished document should not be a sequence of posters.

Use a hierarchy of page types:

1. reading pages for sustained text;
2. evidence pages for charts/tables/figures;
3. transition pages only when they improve navigation;
4. appendices/reference pages for functional density.

This creates rhythm without visual noise.

## Density management

When a page is overloaded, do **not** immediately reduce font size.

Try, in order:

1. remove redundant wording;
2. restructure the information;
3. split an oversized table;
4. move secondary material to notes/appendix;
5. change page composition;
6. use columns when semantically appropriate;
7. only then make modest typography adjustments.

When a page is too empty, do not fill it with decoration. Improve hierarchy, add genuinely useful supporting information, or allow the whitespace to remain intentional.

## Visual storytelling

For each major section ask:

- What is the one thing the reader should understand?
- What evidence supports it?
- What should be scanned versus read deeply?
- Is a table, diagram, timeline, or chart clearer than prose?

A visual should reduce cognitive work, not merely increase visual interest.

## Redesign protocol

When redesigning an existing document:

1. preserve factual content;
2. identify the current information architecture;
3. identify what is visually weak;
4. propose a stronger visual system;
5. rebuild using semantic document structures;
6. render the result;
7. compare old vs new at page level;
8. fix regressions;
9. validate content preservation.

Do not confuse "different" with "better."

## K3-style autonomy, with boundaries

For an underspecified request, infer sensible design choices from audience and document type, but do not invent facts, logos, statistics, citations, or institutional requirements.

If a supplied template establishes branding, treat the template as authoritative unless the user explicitly asks for redesign.

If the user says "make it look better," improve the highest-impact visual problems first rather than adding arbitrary features.

## Final art-direction questions

Before delivery:

- Does the first page establish a clear identity?
- Can a reader understand the hierarchy in seconds?
- Is the body comfortable to read for several minutes?
- Do tables look designed for their data rather than copied from a spreadsheet?
- Do figures have consistent captions and scale?
- Are page transitions intentional?
- Is the design restrained enough to remain credible?
- Does every repeated component belong to the same visual language?
- Does the document still look good when printed or viewed without color?
- Would the design still make sense if all decorative elements were removed?
